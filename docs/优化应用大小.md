# 优化应用大小

对照 [Tauri 官方「应用体积」](https://v2.tauri.org.cn/concept/size/) 逐条评估后在本项目的落地结论：哪些加了、哪些没加、为什么。配置改动在根目录 `Cargo.toml`（profile）、`src-tauri/tauri.conf.json`（`removeUnusedCommands`）与 `src-tauri/capabilities/default.json`（权限收敛）。

## 结论速查

| 项 | 结论 | 一句话理由 |
| --- | --- | --- |
| `codegen-units = 1` | 已加 | 与 `lto` 配套，体积收益的主要来源之一；代价是编译变慢 |
| `lto = true` | 已加 | 链接时优化；代价是链接耗时与内存占用升高 |
| `opt-level = "s"` | 已加 | 优先体积；CPU 密集在 `image` 解码与 `jpeg-encoder`，若压测有回归改 `"3"` |
| `panic = "abort"` | 已加 | 全仓无 `catch_unwind`/`panic::set_hook` 依赖展开，单测走 dev profile 不受影响 |
| `strip = true` | 已加 | release 默认不生成调试信息，但符号表仍在，剥掉后体积明显下降 |
| `incremental = true`（dev） | 已加（显式化） | cargo 对 dev/test profile 默认已开启，写上只是显式化 |
| `removeUnusedCommands: true` | 已加 | 版本门槛全满足；配合权限收敛才有意义，见第二节 |
| profile 写在 workspace 根 | 必须的修正 | 官方文档示例写在 `src-tauri/Cargo.toml`，本项目根 `Cargo.toml` 是 workspace 根，写在成员里会被 cargo 忽略并告警 |
| `trim-paths = "all"` | 未加 | cargo 1.96 仍标记为未稳定（需 nightly），写上 manifest 直接解析失败 |
| `rustflags = ["-Cdebuginfo=0"]` | 未加 | release 本就不生成调试信息，与 `strip` 冗余 |
| `rustflags = ["-Zthreads=8"]` | 未加 | `-Z` 是 nightly 专有，本项目用 stable |

## 一、Cargo profile

**必须写在根目录 `Cargo.toml`**：根 `Cargo.toml` 是 workspace 根（`members = ["src-tauri"]`），`[profile.*]` 写在成员清单里会被 cargo 忽略，并告警 `profiles for the non root package will be ignored`。官方文档示例是按「src-tauri 独立 workspace」写的，本项目不能照抄位置。

已写入（根目录 `Cargo.toml`）：

```toml
[profile.dev]
incremental = true

[profile.release]
codegen-units = 1
lto = true
opt-level = "s"
panic = "abort"
strip = true
```

取舍说明：

- `opt-level = "s"` 是官方建议值与性能之间的折中。本项目的 CPU 密集环节是缩略图重建与备份导入（`image` 解码 + `jpeg-encoder`），若用 `scripts/bench-data.mjs` 压测发现回归，把这一项改成 `"3"` 即可，其余项不受影响。
- `panic = "abort"` 的代价是 release 下任一 panic 直接终止进程，`paim.log` 只能记到 panic 之前的行；排查仍靠日志与 `set_log_level` 热切。
- `lto + codegen-units = 1` 会让 release 构建明显变慢（依赖里有 `rusqlite bundled`、`image`、`zip`），只在 `pnpm release` 时付这个成本，日常 `pnpm check` 走 debug 不受影响。

## 二、removeUnusedCommands 与权限收敛

`removeUnusedCommands` 移除的是「ACL 未允许的命令」，所以**必须先有精确的能力清单**，否则用 `core:default` 时它几乎无事可做（官方原文：为了最大化收益，请不要使用 defaults）。

### 生效条件（本项目全部满足）

- tauri-cli 2.11.4（≥2.4）、tauri 2.11.5（≥2.4）、tauri-build 2.5.6（≥2.1）、插件 2.3~2.9（≥2.1）。
- 只对**经 tauri-cli 的构建**生效：`pnpm dev` / `pnpm release` 会设置环境变量 `REMOVE_UNUSED_COMMANDS`，裸 `cargo build`（`pnpm build:rs`）不会设置，因此该模式下命令一个都不会被移除——行为差异属预期，不用排查。

### 两个「不会被影响」的确认（源码层面）

- **自定义命令不会被移除**：`tauri-macros` 的 `filter_unused_commands` 里有 `if plugin_name.is_none() && !allowed_commands.has_app_acl { return; }`——没有 app ACL 时应用自有命令全部保留。tauri-specta 的 `collect_commands!` 展开后仍是 `::tauri::generate_handler!`，机制同样适用。e2e 测试缝命令（`e2e_*`）也在此列，不会被误删。
- **Rust 侧插件 API 不受影响**：启动防呆的 `app.dialog().message(...)` 走 `run_on_main_thread` + 插件内部实现，global-shortcut 的注册走 `run_main_thread!` + 内部 manager，都不经过 IPC，因此不需要给它们开权限，也不会被移除。

### 审计方法与结果

审计依据只有两处：前端实际调用的 Tauri API（`grep "@tauri-apps/" src/`），以及构建生成的 ACL 清单 `src-tauri/gen/schemas/acl-manifests.json`（用它把权限展开成命令集合来量化）。

前端实际用到的：

| 来源 | 用法 | 需要的权限 |
| --- | --- | --- |
| `@tauri-apps/api/core` | `convertFileSrc` | 无（纯本地路径转换，不发命令） |
| `@tauri-apps/api/core` | `invoke`（bindings 生成） | 无（应用自有命令不受 ACL 约束） |
| `@tauri-apps/api/event` | 仅 `listen`（bindings 的 `events.*.listen`），返回的 `unlisten` 会被调用 | `core:event:allow-listen`、`core:event:allow-unlisten` |
| `@tauri-apps/api/window` | `getCurrentWindow().setFullscreen(true/false)`（全屏查看器） | `core:window:allow-set-fullscreen` |
| `@tauri-apps/plugin-dialog` | `open`（选图/选备份）、`save`（导出备份） | `dialog:allow-open`、`dialog:allow-save` |

未使用：`emit`/`once`（bindings 虽生成但前端不调用）、`getVersion` 等 app API（版本号由 vite `define` 注入）、path/webview/menu/tray/image/resources 任何前端调用。

量化结果：把权限展开到命令级，`core:default` 放行 **92** 条 core 命令；收敛后只放行 **5** 条（`core:event|listen`、`core:event|unlisten`、`core:window|set_fullscreen`、`dialog|open`、`dialog|save`），其余 core 命令与未用的插件命令（dialog 的 ask/confirm/message、log、global-shortcut 的 register 等）都会被移除。

最终 `src-tauri/capabilities/default.json` 只保留这 5 条权限。

### 维护约束

- 前端每新增一个 Tauri API 调用（新的 `core:*` 或插件 API），必须同步往 capabilities 里加权限，否则运行时会 `permission denied`——注意这个错误只在运行时出现，编译期不报错。
- 反过来，`pnpm build:rs`（裸 cargo）不会移除命令，所以「本地跑着没问题」不能证明 release 下没问题；涉及新增 Tauri API 的改动，发布前要用 `pnpm release` 出包验证一次。

## 三、验证方式

1. 记基线：`pnpm release` 前后对比 `target/release/paim.exe` 与生成的 NSIS 安装包体积（首次 release 构建会明显变慢，属 `lto` 预期）。
2. 冒烟：设置页「打开数据目录」、图像右键「打开本地保存位置」、全屏查看器（全屏切换）、上传选图与导出备份（两个 dialog）、缩略图重建与备份进度（event listen）——这些都是被收敛过的权限点，功能正常即说明清单没错。

## 四、未采用项

- `trim-paths = "all"`：cargo 1.96 报 `feature trim-paths is required ... not stabilized in this version`，需 nightly，故只留注释不启用（待稳定后可加）。
- `-Cdebuginfo=0`：release 默认 `debug = 0`，与 `strip` 重复。
- `-Zthreads=8`：nightly 专有。
- 不在该页面内的其它体积选项（如 NSIS 压缩、WebView2 引导程序）暂未评估，`tauri.conf.json` 的 `bundle.targets` 当前只出 nsis。
