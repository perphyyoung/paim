# 内置浏览器使用经验

> 用于在浏览器内复现/验证前端 UI 行为（Tauri dev 场景，如卡片布局、选中态等）。
> 适用：需要「看实际渲染结果」的验证 —— 代码逻辑层排查解决不了、或想快速确认 CSS/测量逻辑时。

## 一、启动与打开

```powershell
# 1. 起 dev（二选一）
cargo tauri dev        # 完整 Tauri（占用 1420）
# 或独立 vite：pnpm dev （占用 1420；端口被占时改 --port）

# 2. 浏览器打开 http://localhost:1420
```

## 二、三条环境约束（踩过的坑）

### 1. Tauri `invoke` 在前端浏览器中不可用

- 纯浏览器访问 `localhost:1420` 时，页面调用 `invoke`（Tauri API）会失败。
- 后果：涉及数据库的页面（提示词/图像主页）恒为空库 —— **无法用真实数据复现**。
- 对策：**构造专用演示数据/页面**（见第四节），不要依赖应用内数据库。

### 2. `file://` 协议被浏览器安全策略拦截

- `file:///…` 打开静态页会失败；把演示文件放进项目（Vite 会静态服务项目根），改用
  `http://localhost:1420/<路径>` 访问。例如 `verify/card-row2-align.html`。

### 3. evaluate 沙箱：块体脚本可能返回 `undefined`

- `browser_evaluate` 执行「块体 + `return`」形式的脚本时，多次出现返回 `undefined`；
  用**表达式体**（箭头/内联表达式）可稳定返回，如
  `JSON.stringify(Array.from(document.querySelectorAll(...)).map(x => x.className))`。
- 可分步跑最简探测脚本（`location.href`、`innerText.includes(...)`）验证沙箱行为，再上复杂查询。

### 附带：SPA hash 路由

- `browser_navigate` 直接改 hash 有时不触发重渲染 → 优先点击左侧导航图标切换页面。

## 三、推荐验证姿势

1. 简单只读：`browser_evaluate` 表达式体取 class/尺寸/textContent，JSON 返回主 agent 分析。
2. 复杂交互（点击/截图）：交给 `browser_use` 子代理并让其返回结构化数据。
3. 会话结束留意浏览器锁释放；锁定中无法操作时先解锁再继续。

## 四、验证产物（可复用，已 gitignore）

| 文件 | 用途 | 复现场景 |
| ----------------------------- | ---------------------- | ----------------------------------------------------------------------- |
| `verify/card-row2-align.html` | `MediaCard` row2 对齐验证页 | 12 张卡（短/中间/超长 40 行），复刻 row2 结构与 measure 逻辑；超长卡应 `items-start` 开头可见、短卡居中 |

- 产物位于项目 `verify/` 目录，**已加入** **`.gitignore`**（不随仓库提交，保留即可复用）。
- 使用：起 dev 后访问 `http://localhost:1420/verify/card-row2-align.html`，或让浏览器子代理打开后 evaluate 检查：
  - 超长卡：`.slot2` 含 `top`，且 `p.getBoundingClientRect().top - row.top ≈ padding`（开头可见）
  - 短/中间卡：不含 `top`（居中）
- 新增同类验证页时：放 `verify/` 下、在 `.gitignore` 无需再改（整目录忽略）、在本文档表格补一行。
