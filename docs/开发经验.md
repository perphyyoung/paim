## 1. 缩略图懒自愈

**要解决的问题**：磁盘上的缩略图可能因为各种原因丢失（手动清理、外部误删、文件损坏），此时卡片 `<img>` 加载失败、画面破图。想要「图没了能自动补回来」，但不能为它付出主动轮询或看盘的成本。

**核心思路**：

- **懒触发，不轮询**：不建立任何定时器主动扫盘，而是搭在「可见窗口有变化」这个既有信号上（滚动、列表数据变化、筛选变化、页面首次渲染）再校验。图只在「需要显示、且发生了重新校验信号」时才被检查——真正用得上才动手。
- **校验与修复分离，按需做贵的**：校验阶段只对可见项做幂等的 `stat`（健康项原样返回，不生成）；只有确认缺图、且原图还在时，才触发真正的重建（解码原图 + 重编码缩略图）。贵操作（缩略图生成）只对缺失项发生，且在 Rust 侧线程执行，不进 webview 主线程。
- **随取随校验，不做一次性记忆**：早期实现曾对每个 id 记「终身只校验一次」，漏掉了「运行中缩略图被删、卡片重新可见」的场景。改成本质上是「每次可见窗口变化都重新 stat 当前可见项」，从而天然覆盖进程重启与运行中删除两种情况，无需为重启维护额外状态。
- **代价用短 TTL 兜底**：对「原图也不存在、确实无法修复」的项记一个短暂节流（短时间内不再重发），防止每次滚动都对损坏来源反复 stat。健康项不进节流，所以正常浏览几乎无额外成本。
- **修复后按需刷新 UI**：重建完成后只更新对应卡片缩略图 URL 映射，并附带 cache-buster（时间戳），避免「URL 全等导致 Vue 跳过 `<img>` 更新、浏览器不重新请求」的坑，让修复结果真实渲染出来。不整表刷新、不滚动复位。

**配套**：

- 行为与边界详见 `缓存及加载优化设计.md` 的自愈一节。
- e2e 覆盖两个场景：进程关闭后删缩略图、运行中删缩略图（滚动触发），见 `e2e/09`。

## 2. 打开目录或文件的推荐方式

**要解决的问题**：让用户在本机文件管理器里看到文件——图像右键「打开本地保存位置」、设置里「打开数据目录」。看着只是「调一下资源管理器」，实际是有坑的系统交互，且失败现象（只打开目录、不选中）容易被误判成偶发。

**推荐方式**：只用 Shell API，不用 `explorer` 命令行。

- 打开目录并选中文件 → `SHOpenFolderAndSelectItems(父目录 PIDL, [文件 PIDL], 0)`。
- 只打开目录 → `ShellExecuteExW` + `explore` 动词。
- 两个动作都收在同一处（本项目 `infra/shell_explorer.rs`：`reveal_in_explorer` / `open_in_explorer`），共用入口归一化、COM 初始化与失败兜底，避免「打开」和「定位」各写一套后逐渐分叉。

**为什么不用 `explorer /select,`**：

- **冷启动竞态（主因）**：目标目录尚无已打开窗口时，新窗口是异步创建的，选中命令在视图创建完成前发出就被丢弃 → 首次只打开目录、第二次才选中文件；窗口已存在时命令派发给现存视图，所以「第二次必中」。这个特征正是判定该竞态的依据。
- **参数形式敏感**：`/select,` 必须单独成一个参数传、路径必须全反斜杠，否则 Explorer 回退到默认位置。
- **无法判断成败**：`explorer` 是独立进程，`spawn()` 成功不代表定位成功，返回码几乎恒 0，排查时拿不到任何信号。

**三个必须做对的细节**：

- **路径先归一化分隔符为反斜杠**：数据库 `relative_path` 用 `/` 存储，`Path::join` 会保留，混用分隔符会让 `ILCreateFromPathW` 直接返回 null（同一个坑换了层皮）。归一化在入口做一次，主路径与兜底共用结果。
- **COM 初始化**：Shell API 要求调用线程先 `CoInitializeEx`；只有返回 `S_OK`（本次完成初始化）才配对 `CoUninitialize`，`S_FALSE`（已初始化）/`RPC_E_CHANGED_MODE`（模式不同）都不能卸，否则拆掉的不是自己的初始化。
- **PIDL 生命周期**：`ILCreateFromPathW` 得到的 PIDL 只引用路径字符串，两者必须同生命周期（同结构体持有），用完 `ILFree`。

**兜底与可观测**：Shell 调用失败记 WARN（这次终于能拿到 HRESULT，不再是「返回码恒 0 无法判断」）后回退 `explorer`，最差仍是打开目录；禁止静默失败——这类问题在用户侧只表现为「没反应」，没有日志就无从下手。Electron 与 tauri-plugin-opener 也是这套组合（后者在 `ERROR_FILE_NOT_FOUND` 时回退 `ShellExecuteExW`），可直接对照。

**配套**：

- 实现见 `src-tauri/src/infra/shell_explorer.rs`，命令入口 `open_image_location` / `open_data_dir`。
- 踩坑经过与逐条根因见 `lessons.md` 第 2 节。

## 3. 全屏查看的体验优化

**要解决的问题**：详情页双击大图进全屏查看，退出后下层详情弹窗会「跳」一下；改成「先等窗口还原、再露出弹窗」后跳动没了，但退出又多了一步「黑底 + 顶栏」的伪全屏帧（约 0.3~0.4s）。两种表现背后是同一件事：**主窗口在切全屏，而切换过程本身是可见的**。

**推荐方式**：让主窗口**完全不参与全屏状态**——查看器跑在自己的窗口里（本项目 `image-fullscreen`：全屏 + 无装饰 + 隐藏创建、用完复用），主窗口只做一件事：把「列表快照 + 起始索引」发过去。关闭时主窗口什么都不用做，查看器隐藏自己即可。

**为什么**：Windows 退出全屏不是原子操作——先恢复窗口装饰（标题栏出现），再套用最大化布局（客户区尺寸变化），而 WebView 的客户区尺寸更新还要更晚一帧。因此只要主窗口切过全屏，退出时必然有一段「装饰已回来、客户区还是旧尺寸」的过渡期，应用只能选择这段过渡期**显示什么**：显示查看器是「黑底 + 顶栏」，显示下层弹窗是「下沿跳动」，锁死下层几何则其它元素照样随视口漂移。更关键的是：装饰与客户区尺寸的变化发生在 WebView **之外**，网页遮罩盖不住标题栏那一段，所以「叠一层盖住下层」这条路走不通。独立窗口方案下主窗口的尺寸与层级全程未变，退出只是「另一个窗口隐藏了」，主窗口连同它最上层的弹窗原样露出，**没有过渡帧**。

**必须做对的细节**：

- **载荷两条来路都要覆盖**：首次创建窗口时页面还没挂载，事件必丢，所以必须有「可取回的 getter」；窗口已存在时走事件推送。两条路收敛到同一个 `apply()`（本项目 `mount_image_fullscreen` + `image-fullscreen-opened` 事件）。
- **先应用并渲染，再让窗口露面**：复用窗口若先 `show()` 再推载荷，会闪一下上一次的内容（本项目由查看器窗口在 `nextTick` 之后自己调 `show_image_fullscreen`）。
- **窗口内状态不要跨次累积**：窗口复用不销毁，组件里的 `src`/标签缓存、缩放要按载荷重建（本项目用 `:key` 强制重建组件）。
- **不要重复实现共用组件的键盘导航**：导航胶囊 `NavAndIndex` 自带 document 级 ←/→、Home/End（设计上「不依赖焦点」），查看器只接它的 first/prev/next/last 事件即可；自己再注册一份同键位监听会让一次按键走两次（索引跳项，≥3 张图才可见，见 `lessons.md` 第 22 节）。同理，胶囊的 document 监听**不区分层级**：查看器/详情弹窗之上再叠一层时，要用它的 `disabled` 停用被盖住的那一份（两个详情弹窗与 Ctrl+F 的 `guard` 共用同一个 `overlayOpen`）。
- **关闭与窗口销毁解耦**：✕ 与 Alt+F4 都只隐藏窗口（复用）；真被销毁了，下次打开重新创建即可，不要出现「没了就打不开」的状态。
- **不要用 URL query 传参**：`WebviewUrl::App` 收的是路径，`?` 能否原样保留取决于内部解析，不划算；本项目用窗口 label 分流（`src/main.ts` 按 `getCurrentWindow().label`）+ 后端状态中转。

**兜底与可观测**：查看器窗口只调应用自有命令 + 监听事件，因此**不需要任何 `core:window` 权限**（原来的 `core:window:allow-set-fullscreen` 随之删除）；窗口创建/显示失败要在前端记日志并隐藏自己，避免留下一个「打不开的窗口」这类死状态。

**代价**（写出来便于判断是否也值得这么做）：多一个 WebView 进程的内存（隐藏后常驻，换来秒开），以及首次进入约 0.3~0.6s 的窗口创建时间。

**配套**：

- 实现见 `src-tauri/src/commands/image_fullscreen.rs`（命令分工见该文件头部注释）与 `src/features/image/FullscreenWindow.vue`。
- 踩坑经过（含第一次不彻底的修复）见 `lessons.md` 第 18 节；权限收敛的同步维护见 `docs/优化应用大小.md`；查看器缓存口径见 `缓存及加载优化设计.md` §5。

## 4. 相似度检索（外部 embedding 服务）

**要解决的问题**：给 paim 加「按内容找相似」——图像以图搜图、提示词以文搜文，且两者能互查（所用模型对图像与文本产出同一空间的向量）。难点不在相似度算法，而在：外部服务不可控（模型 / 投影器 / 启动参数都得实测钉死）、预处理策略必须两侧一致、失效不能靠指纹列、万级长任务不能锁库、结果页要同时容纳两类结果且参数互不干扰。

**核心决策（以及为什么这么定）**：

- **向量不进新表、不存模型指纹**：直接在既有表加一列 `vec BLOB`（f32 LE、写入前 L2 归一化 → 点积即余弦）。失效改用事件驱动策略——「图像替换会产生新 id（旧图软删）」「提示词保存时内容变了就把该行 `vec` 置 NULL」——于是「增量索引」就是 `vec IS NULL`，不需要内容哈希列；代价是换模型或改预处理规则后必须手动点「全量重建」（设置页文案写明）。
- **检索不需要向量索引扩展**：SQL 只做筛选（`is_deleted = 0 AND length(vec) = 维度`），候选整表读回内存算归一化点积 Top-K。1 万条 ≈ 80 MB 读取 + 2000 万次乘加 → 单次 50~100 ms，`sqlite-vec` 之类在这一量级是过度设计；维度不符的旧向量会被自动跳过，`stale` 计数提示该全量重建。
- **不用 `/v1/embeddings`**：该服务非 OAI 的 `/embedding` 在 `--pooling last` 下同样返回**单条已归一化向量**，还不需要模型名；文本用 `{content}`，图像走多模态提交（`/props` 先取 `media_marker` 并缓存——新版是随进程的随机串，不能硬编码）。
- **预处理固定为「JPEG + 长边 1024」**：服务端图像解码器（stb_image）**不认 webp**，直喂会被**静默丢弃**成「假图」——HTTP 200、无报错，但向量与画面无关；本项目图库以 webp 为主，必须在 Rust 侧（`image` crate）解码转码。分辨率影响远大于格式（JPEG ↔ 同内容 PNG `cos = 0.996`，缩图 ↔ 全图 `0.974`），因此**入库与检索必须同一策略**。
- **服务端三个硬约束**：`--embeddings` 必需；`--pooling last` 否则返回逐 token 向量且 `/v1/embeddings` 报 400（`Pooling type 'none' is not OAI compatible`）；`-b 1024 -ub 1024` 否则 1MP 以上图报 `input (…) is too large to process`。另注意 `-np N` 会把上下文总量按份切分（`-np 4` 时每 slot `n_ctx = 3072`，`-np 1` 是 11776），单图 token 数远小于此够用，要放更大的图需显式给 `-c`。
- **主模型与投影器要配套，且别被报错表面信息带偏**：同一故障先报 `Multimodal data provided, but model does not support multimodal requests`（因为没加 `-mm`），加上后又报 `mismatch between text model (n_embd = 2048) and mmproj (n_embd = 8192)`——**看似 mmproj 不配套，真正的主因是主模型 GGUF 的 `general.architecture` 标记**（该文件标 `qwen2vl`，而 mmproj 是 `qwen3vl_merger` 型；8192 = 2048 × 4 是 deepstack 侧维度）。换成官方转换版（标记 `qwen3vl`）后，同一个 mmproj 直接可用。
- **依赖只加 `ureq` + `base64`**：只需要与 127.0.0.1 的明文 HTTP 通信，不必为此引入异步 HTTP 栈或 TLS；索引本身是 CPU 密集的本地任务，阻塞式请求 + 线程池就够。
- **两侧共用一套实现，差异只在「拿什么去编码」**：状态 / 清空 / 写入 / 取向量 / 检索参数化为表名（模块内常量，不来自入参）；图像侧多一步预处理，提示词侧直接送 `content` 原文，且只算内容（标题 / 翻译 / 备注不参与）。
- **检索命令统一成「以任意 source 查某一张表」**：`similar_images(source, source_id, …)` 与 `similar_prompts(source, source_id, …)`，`source = Image | Prompt` 都合法（图像 ↔ 提示词即跨模态，实测匹配描述 0.81、无关 0.18）。一度做成「一次出两侧」的 `similar_mixed`，后因**要求两栏能各自独立重查**而撤销——独立交互就该配独立查询。

**必须做对的细节**：

- **长任务编排**：索引在命令层按「短锁取清单 → 无锁请求服务 → 短锁写回」推进，万级任务不会整段持有 DB 锁把主页查询冻住；进度走**双通道**（事件推送 + managed state 快照——事件不重放，离开设置页再回来靠快照接上）；两条索引各自 `AtomicBool` 重入保护、各自的事件与快照（共用一个快照会互相覆盖）。
- **并发按侧分别定**：实测文本接近线性（16 条：串行 681 ms → 并发 150 ms，**4.5x**），图像受服务端视觉编码 CPU 限制（4 张：串行 2393 ms → 并发 1945 ms，**仅 1.23x**）→ 一侧可开大、一侧开满无益。另注意服务端会缓存**相同图像**的编码结果（重复请求降到 60 ms 级），别拿它当加速比。
- **阈值与漂移**：同内容 `0.996~1.000`、跨模态匹配 `≈0.8`、无关 `≈0.2`，默认 `minScore = 0.5` 两侧都能用；同一输入跨批次会有 ~0.1% 漂移（批切分 / 浮点求和顺序差异，`--no-cache-prompt` 也不保证 bit-exact）→ 判「同一内容」用 `≤0.999`，别用 `>0.9999` 当判据。
- **结果页交互**（多轮迭代的结论）：尺寸与详情页逐字一致；首行是查询源（提示词显示内容；图像**优先显示关联提示词内容**，没有关联提示词才回落文件名）；左右两栏卡片用与主页同形的轻量卡片（图像 = 背景图 + 相似度 + 文件名；提示词 = 背景图 + 相似度 + **内容占最大空间** + 标题）；两栏的条数 / 阈值 / 重置 / 重查**完全独立**，各有草稿态、请求序号与 loading / 空 / 错态，改完必须点该栏「重查」才提交并持久化。
- **点击结果的层级**：同侧结果交给父级按 id 重开详情，跨模态结果在本弹窗内叠加打开另一类详情（复用两侧既有的嵌套写法）；结果页 z 序在详情之上，点击时先关结果页再跳，避免「详情被结果页盖住」。

**测试替身与 e2e（踩坑最集中的一段）**：

- 复用已有的 `PAIM_EMBEDDING_MOCK=1`（`MockEmbedder` 按输入派生确定性伪向量），由 e2e fixture 固定注入 → 索引与检索不需要真实服务；用例覆盖两条入口、两栏独立重查（起点两栏皆空 → 只降一栏则只有它出结果）、跨模态点击跳另一类详情。
- **假数据也要有正确的统计性质**：`pseudo` 早期取值区间是 `[-0.5, 0)`（均值 -0.25，非零均值）→ 任意两条伪向量余弦恒 ~0.75，冒充「相似」，默认阈值 0.5 全命中；改成零均值噪声 + 0.1 的「各向异性基线」（任意两条 ≈0.1，恒正、远低于 0.5）后，阈值 0 全命中 / 默认 0.5 全过滤，并用断言锁住该性质。
- **e2e 两个交互坑**：悬浮面板类 helper 必须幂等（连续调用时第二次点齿轮会被自己的遮罩拦下）；阈值是**持久化偏好**，而同 worker 的 spec 共用同一 WebView2 profile → 用例起点用「重置 + 重查」把参数拉回确定默认、收尾清掉偏好。
- **定位点用真实无障碍属性**（设置面板 `role="dialog" aria-label="设置"`、索引按钮的 `aria-label` 带分组名、结果页两栏 `aria-label="相似图像" / "相似提示词"`），不引 `data-testid`。

**兜底与可观测**：不启动服务时其余功能完全不受影响（只有用户触发索引 / 检索时才连服务，错误是可读字符串 + toast）；索引失败按条计数并显示在摘要里；判断服务是否「真的看懂了图」用 `scripts/probe-embed.mjs` 的**硬指标判定**（带图前后 `prompt_tokens` 增量、与同 prompt 纯文本的余弦、跨模态排序对照），不看模型回答的对错。

**代价**（写出来便于判断是否值得这么做）：向量占库（2048 维 ≈ 8 KB/条 → 1 万条 ≈ 80 MB）；图像索引 ≈ 0.5 s/张（1 万张 ≈ 1.1~1.5 h，瓶颈是服务端 CPU），文本 ≈ 23 ms/条；未启动服务时该功能不可用。

**配套**：实现见 `src-tauri/src/domain/similarity_service.rs`、`commands/similarity.rs`、`infra/embedding_client.rs` 与 `src/features/similarity/`；服务启动命令与实测约束见 `scripts/readme.md`（探针脚本）；用户侧步骤见 `README.md`；目录登记见 `项目架构.md`；容量口径见 `缓存及加载优化设计.md` §1.6 / §7；逐条踩坑见 `lessons.md` 19 / 20；e2e 约定见 `docs/e2e测试.md`。

## 5. 详情弹窗的嵌套：槽位模型（原始详情永不动）

**要解决的问题**：详情弹窗之间会互相跳（相似结果、关联对象、编辑入口）。一旦允许「详情里再开详情」，就必须给层数一个**显式上限**——否则要么越点越多（每层都是全屏遮罩，用户会彻底迷失），要么用「隐藏入口」硬挡，把功能变成静默失效。本项目就踩过后者的坑：嵌套态的提示词详情内容右键**菜单是空的**（看起来像「没有右键菜单」），根因与排查经过见 `lessons.md` 第 24 节。

**推荐模型**：把嵌套层当**槽位**，而不是栈。

```
第 0 层  原始详情（页面级）              ← 从主页打开的那个详情，全程不动
第 1 层  第 0 层的「跨类」嵌套槽（各一个）  ← 图像详情里嵌一个提示词详情 / 反之
第 2 层  第 1 层的「跨类」嵌套槽（各一个）  ← 最多再一层
```

两条规则表达所有跳转（对任何一层都成立）：

- **同类结果 → 换掉那一类已有的那个槽**（顶层详情的同类结果由页面换当前详情，保持「详情内换条」的既有语义）；
- **跨类结果 → 用本层自己的跨类槽**（已有内容则替换，不新开层）。

**为什么这么定**：

- **第 0 层永不被替换**，层数有上限（本例 ≤ 3）：用户任何时候逐层 ✕ 都能回到最初那个详情，不会「回不到出发点」；
- 「换槽」而不是「压栈」让语义可预测：连点几次结果，层数不涨，只是那一层的内容在换；
- 跨类槽各一个 → 图像 / 提示词各最多一层，**槽之间互不牵连**（换提示词槽不会关掉图像槽，两者各自独立替换）；交替跳转也不会无限套娃，层数恒定有界。

**必须做对的细节**：

- **把槽位交给一处持有，别让每个调用方自己接线**：本项目是「页面 `provide` 一份 `useNestedDetails` + 渲染 `<NestedDetailSlots>`」，两个详情弹窗只调 `openNested(kind, id)` —— 槽位上限、实例重建、槽间互不牵连全在这一处。早先散在两个弹窗里（各持一个跨类槽 + `isNested` / emit 上抛分支 + `:key`），每加一条路径都要在两层各接一次线：漏接的表现不是报错，而是**点了没反应**（同类结果无人接）或**再叠一层**（跨类结果落进内部槽），排查成本远高于抽象成本（见 `lessons.md` 24 / 25）。
- **槽内容换代即换实例**：详情当前项由「进入那一刻」的快照固定（`useDetailSnapshot` 只在初始化 `init()`），而换槽只是改 props → 渲染层必须把 `:key` 绑到**槽内容 id** 上强制重建，否则 `current` 停在旧 id（大图变「无图像」或内容不更新，见 `lessons.md` 第 25 节）。
- **事件用「信号」而不是回调链**：槽由页面持有，回调表达不了「谁打开的」；改成栈上的两个信号 —— `revision`（内容变了：编辑 / 换图 / 安全联动）与 `safeSynced`（联动的值），**宿主详情 watcher 订阅**，各自决定重拉哪份关联数据 / 回写哪张卡片（同上）。
- **别用「条件隐藏入口」当层数护栏**：`v-if="enabled && !isNested"` 这类写法会把「不该做的跳转」变成「按了没反应」，既让菜单变空盒子、也让后来想放开时找不到线头。护栏应做在**跳转目标**上（换槽）；确需限制入口时用置灰 + `title` 说明理由（本项目对「查看图像详情 / 编辑提示词」就是置灰 + `title="禁止二级跳转"`，属于可接受写法，且后续同样能按本模型放开）。
- **测试要断言「层数 + 内容」，并自顶向下关闭**：层数对 ≠ 内容对（`lessons.md` 25 就是「层数对、内容是空的」）；槽位是叠放的，e2e 关闭必须自顶向下，否则下层弹窗的关闭钮会被上层遮罩拦下。

**代价**（写出来便于判断是否值得这么做）：多一个共享状态（栈）与一个渲染组件，页面必须 `provide`（详情弹窗在没注入时直接报错，避免静默失效）；换来的是规则集中在栈 + 槽位组件两处，调用方只剩「打开哪一类槽」。

**配套**：实现见 `src/composables/useNestedDetails.ts`（两槽 + `openNested` + `revision` / `safeSynced` 信号）、`src/components/NestedDetailSlots.vue`（页面级渲染，`:key` 绑槽内容 id），两个详情弹窗只调 `openNested`；e2e 覆盖见 `e2e/11` 第 3 条（嵌套层菜单可见 → 跨类结果落槽 → 同类只替换 → 槽位互不牵连 → 逐层关闭后底部原样）；踩坑经过见 `lessons.md` 24 / 25。
